# XHigh 參考分析：模式檔

> 由 `analyze-style/SKILL.md` 依觸發詞載入；共用規則在 SKILL.md。規格識別：`xhigh-text-20261103-r2`。

## 本模式的分析目的

以證據為基礎，把已界定問題分解為可查核的判斷，再整合成完整答案。將本 Skill 視為自訂工作規格；對官方模型內部過程、已使用的算力與效能改善幅度，以可核對資料為準。

## 品質規則

- 以繁體中文說明，程式註解也使用繁體中文。
- 對重要判斷使用四種狀態：已確認、條件式判斷、待確認、證據衝突。
- 已確認事項附對話中的證據位置、適用範圍及確認層級，例如「依所提供紀錄可確認」。材料互相一致與外部事實已查證分開標示；將使用者推測保留為待核對主張。
- 條件式判斷寫成「若前提成立，則結果成立」，附前提的驗證方式。
- 缺少關鍵證據時，寫「【資料不足，無法確認】」，完成其餘可回答部分並指出最小補充資料。
- 保留資料型別、單位、版本、環境與範圍；將必要與充分條件、現象與原因分開說明。
- 呈現精簡、可查核的理由、必要計算與條件表。交付判斷摘要與證據即可。
- 已執行或已測試的聲明附實際結果；文字推算及程式檢查標示為靜態分析。

## 分層工作法

按任務需要合併或回訪各層。簡單題直接回答；複雜題才展示必要表格。新的反例改變前提時，回到受影響的子問題。

### X1 固定問題與成功條件
明確界定輸入、預期結果、限制與本題要證明的主張。目的在確保分析回答同一個問題。只釐清會改變判定的重要缺口。

### X2 依相依關係拆解
按資料流、控制流或前置條件列出必要子問題，標出誰依賴誰。目的在避免下游使用尚未成立的上游結論。每個子問題都需對主問題有貢獻。

### X3 核對證據與關鍵假設
依下列資料查核協定，將關鍵前提對應到程式、原始資料、來源與待補資訊，核對事件識別、型別、環境及版本。目的在找出會改變後續推導的未知條件。每個關鍵假設都有查核方法。

### X4 完成可查核的局部推導
逐項核對實際條件、型別、邊界及原值與轉換，建立必要的輸入輸出對照；依需要用另一種可查核方法重算。目的在讓局部結果可分別檢查。把程式實際行為與業務需求分開列出，文字推算標示為靜態分析。

### X5 比較與排除候選解釋
對仍有歧義的問題，保留有依據的候選，將各自預期觀察與現有證據比較，指出支持、衝突與排除條件。目的在縮小範圍。對已由證據決定的題目直接給結論；候選數量依問題而定。

### X6 檢查反例與邊界
針對最關鍵結論，檢查一個能改變判定的反例或邊界條件，並按其餘具體風險補充。目的在確認結論的適用範圍。未知的行為轉為待驗證項目。

### X7 整合相依結果
把各段結論放回原始流程，核對它們使用同一版本、環境與前提。前提修正時，回查所有受影響的下游結論。目的在確保局部正確能支持整體答案。以證據處理交互影響，未解矛盾清楚保留。

### X8 驗收與結束
對照 X1，交付結論、關鍵依據、適用條件與最小驗證步驟。目的在分開分析成立、可執行與實測成功。證據足夠時結束；不足時指出阻擋判斷的資料。

## A1 把結論拆成可查核主張
為影響答案的主張建立簡短代號 C1、C2，列出其證據 E1、E2。代號只用於本題索引。優先處理一旦錯誤就會改變局部結果、造成較大影響或阻擋判定的前提。簡單題用一句對照即可，避免填滿無關欄位。

## 題型檢查

Java 條件：列輸入、實際結果與業務預期，檢查空值及邊界。Java 與 SP：對照名稱、位置、型別、預設值及實際呼叫方式。SQL：以題設的少量資料列追蹤 JOIN、篩選位置、NULL、重複與聚合，標示靜態推算。數值：核對單位、分母與總和。log：以同一事件、時間、環境列支持及反對各候選的紀錄。僅使用已提供語義；關鍵規格不明時列出待查項目。

## 回答形式與停止條件

先說結論或可判定範圍，再給決定性條件、必要證據與反例，以及待執行的驗證方法。重要結論交代證據位置、適用範圍與確認層級。需要時附精簡主張與證據表，以及實際查核批次的發現摘要；不展示無效角色對話或虛構查核紀錄。使用與任務相稱的長度。

足以滿足成功條件時交付。缺資料時完成可確認部分並提出最少補充需求。沒有新證據或新的具體檢查方法時，將剩餘缺口交付，結束重複改寫。同資料下仍有矛盾時，說明矛盾，讓使用者決定補資料、縮小範圍或調整實際模型設定。

續接保留目標及狀態、計畫及相依、覆蓋範圍、原始證據與來源關係、現有及已撤回的局部結果、假設分支、未解問題、已完成查核及下一步。將同模型再次覆核標為追加檢查；另取得資料後仍需核對其來源獨立性，才能稱為獨立佐證。

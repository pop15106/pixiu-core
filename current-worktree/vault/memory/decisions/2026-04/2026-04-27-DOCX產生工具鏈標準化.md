# 決策：DOCX 需求規格文件產生工具鏈標準化

## 決策點

將本次 DOCX 文件產生經驗沉澱回 `make-docx` skill，並新增可重複使用的需求規格文件產生腳本。

## 選擇

- 更新 `%PIXIU_CORE%\skills\make-docx\SKILL.md`
- 新增 `%PIXIU_CORE%\skills\make-docx\scripts\make_requirement_docx.py`
- 將中文編碼踩坑寫入 `vault/after-action`

## 棄選方案

| 方案 | 棄選原因 |
|------|----------|
| 每次臨時重寫 Python 腳本 | 容易重複踩 PowerShell 中文編碼坑，也不利於跨 session 複用。 |
| 只保留本次 workspace 腳本 | 無法讓其他接線母體的 AI 共用。 |
| 改用 PowerShell 直接產生 OOXML | 可行但維護成本較高，且中文與排版控制更容易出錯。 |

## 原因

這類「主管可讀的 Word 需求規格書」會重複出現，適合變成 skill + script。將中文內容放在 UTF-8 檔案中，再由 Python 讀取或執行，比 PowerShell 管線穩定。

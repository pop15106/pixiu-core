## 已重現的問題與修正

所有問題重現都使用隔離測試資料，沒有以使用者的正式目錄作破壞性測試。

| 問題 | 直接證據 | 修正 |
| --- | --- | --- |
| 特殊字元使實際輸出超過預算 | 舊讀取器回報 12,000 bytes，實際 JSON 輸出為 24,183 bytes | 按完整編碼後輸出計算大小，包含欄位及結尾換行；續讀仍能還原完整原文 |
| 來源根目錄連結未被拒絕 | 舊驗證器接受指向另一目錄的 `references/core` | 讀取前檢查根目錄、每層路徑及檔案型別，核對全部來源與未登錄檔案 |
| 匯入器可沿空目錄連結寫出目的地 | 隔離案例在指定來源目錄外產生 9 個測試檔 | 匯入前拒絕符號連結、Windows 目錄連結與特殊檔案；驗證封存的正規路徑及映射後檔名衝突 |
| 產生索引失敗前，舊來源已遭移除 | 舊流程先刪除舊 core，再產生版本與索引 | 先完整產生新副本，再交換目錄；交換失敗還原原副本，還原失敗保留備份 |
| 需求文字的命令範例沒有說明安全傳參 | 文件直接把原始需求放在 shell 命令內 | 以參數陣列、`shell: false` 傳入文字，無法安全傳參時使用能力索引 |
| 部分工具操作缺少目標與授權範圍 | LLM 評測規格包含自動安裝、停服務、強制重啟；CTF 規格包含依程序名稱強制停止及刪設定 | 核對指定環境、目標與既有授權；記錄恢復方式；動態分析限於已授權測試，按核對後的 PID 處理 |

以上是本次查核可獨立確認的問題，**不是平台掃描拒絕原因的判定**。平台未提供檔案或規則層級的診斷，掃描觸發原因仍無法確認。

## 功能與上下文驗證

已在 Linux 工作副本執行以下命令；Windows 工作機的 Python 命令使用 `python`：

```sh
node --test scripts/chatgpt-core/template/scripts/skill.test.cjs scripts/codex-native-core/publish.test.mjs scripts/performance/lazy-loading-integration.test.js
python3 scripts/chatgpt-core/template/scripts/import-snapshot.test.py
```

結果：兩個環境均為 Node.js 31 項通過（ChatGPT 適配 9、原生發布 13、按需載入 9），Python 匯入 8 項通過；每個環境合計 39 項，零失敗、零跳過。

Windows 首次執行時，兩項 Python 連結案例因符號連結權限不足而跳過。補上 Windows 重新解析點檢查，並使用不需該權限的 junction 測試相同邊界後，8 項重新執行全數通過。

啟動內容實測（bytes；換行格式使兩個工作副本的大小不同）：

| 入口 | Linux 工作副本 | Windows 工作機 | 既定上限 |

既定預算未放寬。這些是入口檔案的 bytes 預算，不是 ChatGPT token 容量，也不保證長對話永遠不需要摘要。

# Dev Workflow SOP — 標準開發流程

> 所有 AI 執行開發任務時必須遵循此流程。
> 與 `%PIXIU_CORE%\rules\common\development-workflow.md` 對齊。

## 標準開發流程

```
1. 理解需求
   ├─ 複述需求（3-5 點）
   ├─ 確認限制條件
   └─ 等待使用者確認理解正確

2. 提出方案
   ├─ 給 2-3 個選項
   ├─ 每個選項含：優點 / 代價 / 風險
   └─ 等待使用者選擇

3. 制定計畫
   ├─ 列出執行步驟（每步驟含驗證方式）
   ├─ 標明改動範圍（哪些檔案、哪些行）
   └─ 等待使用者確認（「確認執行」）

4. 執行
   ├─ 最小改動原則
   ├─ 每完成一個步驟標記完成
   └─ 遇到意外立即停下報告

5. 驗收
   ├─ 說明改了什麼（不需要逐行解釋）
   └─ 提醒是否需要更新 memory-summary.md
```

## 分支操作規範

```bash
# 新功能
git checkout -b feature/tv_{user}_{描述}

# 合併路徑
feature/* → r_sit → r_uat → master
```

## 風險等級標記

在計畫中標記每個步驟的風險：

| 標記 | 意義 | 需要確認 |
|------|------|---------|
| 🟢 低風險 | 單檔修改、可輕易還原 | 可自動執行 |
| 🟡 中風險 | 多檔修改、邏輯變更 | 需使用者確認 |
| 🔴 高風險 | DB 異動、架構變更、刪除 | 必須明確授權 |

## 禁止事項

- 禁止在計畫確認前寫入任何檔案
- 禁止「順便」優化非需求範圍的程式碼
- 禁止跳過分支，直接在 master 上改動

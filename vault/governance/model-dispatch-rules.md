# 模型調度守則

> 適用於所有接線母體的 AI。規則以「能力階層」描述，避免綁死特定型號；型號對照見第 3 節，會過時的資訊集中在那一節。

## 1. 指揮官不下場

主對話（指揮官）的 context 是最貴的資源，只保留：**結論、決策、風險、下一步**。

以下操作一律派 subagent（或單體模式下用第 7 節替代）：

- 大量讀取（一次要看 3 個以上檔案的全文）
- 掃 repo（找某 pattern 在哪些檔案出現）
- 查網頁 / 查文件
- 批次改檔（同一修改套用到多處）
- 機械比對（兩份清單、兩個 schema、兩包 diff 的差異）
- 重複驗證（跑測試、read-back、逐項檢查驗收條件）

**判準**：產出會超過 30 行原始內容（程式碼、log、檔案清單）就不該進主對話——派工，落檔，回傳路徑。拿不準會不會超過＝當作會超過（保守預設），或先派低階模型探一次規模。

## 2. 派工三件套

每次派工的 prompt 必含三件事，缺一件就是不合格派工：

1. **目標與動機**：做什麼＋為什麼（動機讓 subagent 在邊界情況做對取捨）。
2. **驗收條件**：可勾選的清單，每條可被證據驗證。
3. **回報格式**：明確規定回什麼、不回什麼（見第 4 節回報合約）。

填空模板見 `vault/governance/delegation-templates.md`，五種任務型態各一份，直接套用。

## 3. 能力階層與型號對照

規則用三個階層描述：

| 階層 | 用途 | 特性 |
|---|---|---|
| **低階** | 機械操作：格式轉換、批次套用已知模式、簡單搜尋 | 便宜、快，錯一次就升級 |
| **中階** | 預設工作馬：實作、除錯、單模組分析、審查初稿 | 大多數任務停在這層 |
| **高階** | 架構取捨、跨模組根因、高風險判斷、對抗審查 | 貴，用在判斷而非勞力 |

**規則**：任何 session 要顯式指定 model / effort 前，先用上表「驗證狀態」欄的查法確認本機實際可用值；查不到就沿用該環境預設並在回報中註明「模型未顯式指定」。**禁止憑印象填型號。**

### effort 使用原則

- 有 effort / reasoning 參數的環境：機械任務用最低檔，除錯與分析用中檔，架構與對抗審查用最高檔。
- 沒有此參數的環境：以「模型階層」代替 effort 分檔，不要模擬不存在的參數。

## 4. 回報合約

subagent 回報必須遵守：

1. 只回**結論**與**證據指標**（格式：`檔案路徑:行號`），不回推理過程。
2. 長產物（分析、清單、diff、log）**落檔**到指定路徑，回報只傳路徑＋3 行內摘要。
3. 回報上限 30 行。超過＝落檔後重新回報。
4. 明確區分三種狀態：`完成`（附驗收條件逐條勾選）、`部分完成`（列出缺什麼）、`失敗`（照模板回報失敗軌跡，見 delegation-templates 第 7 節）。
5. 禁止把整篇分析塞回主對話；指揮官收到超長回報，應退回要求落檔。

## 5. 升降級路徑

- **低階錯一次**：不重試，直接升中階，附上錯誤輸出。
- **中階同一子任務連錯兩次**：升高階，必須附完整失敗軌跡（兩次的 prompt、輸出、錯在哪）。不附軌跡的升級無效——高階會重犯一樣的錯。
- **高階解出模式後**：把解法寫成具體步驟或規則，降回低階／中階批次套用。高階不做重複勞動。
- **重試上限**：同一件事最多兩輪（一輪＝一次派工＋一次修正）。兩輪後仍失敗＝方向錯了，回 `judgment-rubrics.md` 第 4 條換路判準，不是換個模型再試一次。

## 6. 驗證不自驗

寫的人不驗自己的東西：

1. **驗收派 fresh-context agent**：驗收者只拿「驗收條件＋產出物路徑」，不拿實作過程，避免被實作者的思路帶著走。
2. **檔案用 read-back**：宣稱寫入的檔案，由驗收者重新讀出，確認存在、完整、非亂碼（UTF-8 檢查）。
3. **程式碼用測試或實跑**：能跑測試跑測試；不能跑測試至少編譯＋走一次主路徑。「看起來對」不是驗證。
4. **高風險判斷加第二意見**：DB 異動、跨模組修改、安全相關結論，派一個獨立 agent 用相反立場審一次（「請找出這個方案會出錯的情況」）；或產 2-3 個候選方案交評審選優。
5. 驗收結果寫進回報，格式：驗收條件逐條 `✅/❌＋證據`。

## 7. 單體模式（無 subagent 的環境：如 Gemini CLI）

沒有派工能力時，把「指揮官／工人」的分工轉成「分段／自驗」：

1. 開工前先寫出：目標、驗收條件、步驟清單（等同派工三件套，寫給自己）。
2. 每完成一段，對照驗收條件自查一次，才進下一段。
3. 長輸出照樣落檔，對話只留結論——第 4 節回報合約對自己同樣適用。
4. 「驗證不自驗」退化為：驗證時**重新讀檔案本身**，不憑剛才的記憶；測試實跑不可省。
5. 升級路徑退化為：連錯兩次後停下，把失敗軌跡寫進 recap，明確告訴使用者「此任務建議換更強的環境（如 Claude Code 高階模型）處理」。

## 本檔維護

- 第 3 節型號對照：任何 session 實測後可自行更新，加註驗證日期。這是本檔唯一預期常改的地方。
- 其他節屬制度變更：先問使用者。

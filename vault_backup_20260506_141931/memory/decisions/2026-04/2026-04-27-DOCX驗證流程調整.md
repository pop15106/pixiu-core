# 決策：DOCX 驗證流程調整

## 決策點

調整 DOCX 文件輸出後的驗證流程，避免每次重跑已知在本機失敗或無效的自動視覺驗證。

## 選擇

- 後續不再預設執行 `artifact-tool render_docx.py --renderer artifact-tool`。
- 後續不再預設執行 Chrome headless PDF 截圖驗證。
- 改採 Word COM 開檔、更新 TOC、匯出 PDF。
- 用 PDF 頁數、封面/目錄/章節文字抽取與關鍵字檢查確認輸出有效。
- 若需要視覺 QA，改用人工開啟 Word/PDF 抽查，或等可靠 renderer 修復後再恢復自動截圖。

## 棄選方案

| 方案 | 棄選原因 |
|------|----------|
| 每次都重跑 artifact-tool | 已知本機環境失敗，重試成本高且不產生有效結果。 |
| 每次用 Chrome headless 截 PDF | 目前截圖只取得深色空白 viewer，無法檢查版面。 |
| 完全不驗證 | DOCX 仍需確認可開檔、目錄可更新、PDF 可輸出與關鍵內容存在。 |

## 原因

驗證的目標是降低交付風險，不是完成形式上的工具步驟。既然 artifact-tool 與 Chrome headless 在目前環境無法提供有效訊號，應改用穩定可重現的 Word/PDF 驗證流程；必要的視覺檢查則改成人工抽查或等待可靠 renderer 後再自動化。

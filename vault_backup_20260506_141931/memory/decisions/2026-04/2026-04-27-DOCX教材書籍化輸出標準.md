# 決策：DOCX 教材書籍化輸出標準

## 決策點

將「教材型 / 書籍型 DOCX」的輸出流程納入 `make-docx` 經驗：正式教材應具備封面、可更新目錄、章節導覽、PDF 版面驗證，而不是只輸出正文。

## 選擇

- 使用乾淨 DOCX 重建，避免繼承來源檔案的 OOXML 樣式技術債。
- 第一頁放封面，第二頁放 Word TOC field 目錄，正文從後續頁開始。
- 使用 Word COM 更新目錄欄位並匯出 PDF。
- 驗證流程以 Word COM 匯出 PDF、PDF 頁數/文字抽取與必要時人工視覺抽查為主。
- 2026-04-27 後續決策：不再預設執行 artifact-tool 或 Chrome headless PDF 截圖，詳見 `2026-04-27-DOCX驗證流程調整.md`。

## 棄選方案

| 方案 | 棄選原因 |
|------|----------|
| 直接修改原 DOCX | 原檔可能有隱藏樣式問題，且會破壞原始版本。 |
| 靜態手寫目錄 | 頁碼無法隨內容變動自動更新，不像正式書籍。 |
| 只檢查檔案是否存在 | DOCX 最常見問題是可開檔、目錄、頁數或內容缺漏，仍需 PDF/文字檢查與必要時視覺抽查。 |
| 手動修補 styles.xml 去重 | 可能讓 Word 判定文件毀損，不適合作為通用修法。 |

## 原因

教材型文件的品質重點是讀者導覽與可讀性。封面建立正式感，目錄建立導航，Word/PDF 驗證確保交付結果不是「檔案存在但不可用」。自動視覺驗證待可靠 renderer 修復後再恢復，不再預設重跑已知失敗的工具鏈。

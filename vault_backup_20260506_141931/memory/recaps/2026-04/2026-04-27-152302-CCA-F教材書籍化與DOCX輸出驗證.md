## 📐 當前規劃完整內容

教材型 DOCX 的穩定流程應採：

1. 先抽取原文件結構，判斷章節、表格、風格。
2. 若原檔 OOXML 樣式有技術債，不直接在原檔內硬修，改用乾淨 DOCX 重建內容。
3. 封面放在第一頁，目錄放在第二頁，正文從第三頁後開始。
4. Word 自動目錄用 TOC field 建立，再用 Word COM 更新欄位並保存。
5. 若 artifact-tool 可用，照文件技能規範 render PNG；若不可用，改用 Word 匯出 PDF，再用 Chrome headless 截代表頁檢查。
6. 最後交付 DOCX，PDF / PNG 只作內部 QA，除非使用者需要。

## 🎯 重要決策（含棄選方案）

| 決策點 | 選擇 | 棄選方案 | 原因 |
|--------|------|----------|------|
| 補強方式 | 新增深度補充篇，不覆蓋原始桌面檔 | 直接改原檔 | 可保留原始版本，降低破壞風險。 |
| 文件生成策略 | 乾淨重建 DOCX，再複製原內容與補充篇 | 在原始 OOXML 上直接修補 | 原檔有重複 Heading 樣式，artifact-tool 會報錯。 |
| 目錄方式 | Word TOC field + COM 更新 | 靜態手寫目錄 | 正式書籍應有可更新頁碼。 |
| 驗證方式 | Word 匯出 PDF + Chrome 截圖 | 只檢查 DOCX 存在 | 文件交付要確認版面，不只確認檔案大小。 |

## ⚠️ 發現的問題 / 踩坑

- 原始 DOCX 的 `word/styles.xml` 存在重複 `Heading1 / Heading2 / Heading3` styleId。
- artifact-tool 對重複樣式會報 `Argument_AddingDuplicateWithKey, Heading1`。
- 手動去重原檔樣式表後，Word 可能回報文件毀損；不要把 OOXML style 去重當成通用修法。
- 本機 artifact-tool 連簡單 DOCX 都失敗，代表渲染工具鏈本身可能有環境問題。
- `pdf2image` 因缺 Poppler 不能轉圖。
- Node REPL MCP 因本機 Node v16 不符合需求，改用 bundled Node + `NODE_PATH`。
- Chrome headless 在 sandbox 內啟動會 `spawn EPERM`，需 escalated 執行。
- Word TOC 欄位若不經 Word 更新，DOCX 內可能只顯示 placeholder。
